The most common question about Hash Bin is whether uploads are private. The honest answer is: they're unlisted. Anyone who has a file's link can open it. But nobody can find the file without the link. Both halves of that sentence matter, so let's take them one at a time.

<break time="1.5s" />

Hash Bin has no search, no directory, and no list of recent uploads. That's a deliberate design choice. The only way in is the two-fifty-six T string.

And you can't guess one. For anything bigger than sixty-four bytes, the string contains a five-hundred-twelve-bit fingerprint of the file. Guessing a valid one at random is hopeless, for the same reason we saw in the episode on the string itself: the space is unimaginably large.

<break time="1.5s" />

Now the other half. A link is easy to share, and that cuts both ways. Once you've given it to someone, they can give it to anyone else, and Hash Bin can't tell the difference. So treat the link like a password: share it with the people you mean to share it with.

Two details follow from how the string is built. Tiny files, sixty-four bytes or less, are stored inside the link itself. So anyone who sees the link, in a chat log or a screenshot, has the content, without opening anything.

And because the name comes from the content, anyone who already has a copy of a file can compute its name and check whether it's on Hash Bin. They can't discover new files that way. But they can confirm that a file they already have is there.

<break time="1.5s" />

So what about files that really are private? Hash Bin stores everything encrypted on its servers, but that's not what protects you here, because anyone with the link gets the file back in readable form.

If a file is sensitive, encrypt it yourself before uploading, with any tool you trust, and send the password to the recipient a different way. Hash Bin then only ever holds scrambled bytes, and the link alone isn't enough.

<break time="1.5s" />

What does Hash Bin show the world about a file? Its size, when it was uploaded, when it expires, and its status. If it's deleted, the public records say when and why. If someone reports it, the report is public too.

What it doesn't show is who uploaded it, or who paid for it. Uploaders aren't listed anywhere public. That said, unlisted isn't anonymous to Hash Bin itself: your account is tied to your uploads and payments, and the Privacy Policy explains when that information can be shared.

Hash Bin also doesn't scan or inspect what you upload. It treats every file as opaque bytes.

<break time="1.5s" />

Last, a word about safety for the people opening your links. Files are served from a separate address, two-fifty-six T dot U S, not from hash bin dot org, where accounts live. Browsers keep the two completely apart. On top of that, files are served with strict rules that stop scripts from running at all. So even if someone uploads a booby-trapped web page, opening it can't touch anyone's Hash Bin account.

<break time="1.5s" />

Unlisted, not private. The link is the key, so share it carefully, and lock sensitive files yourself. Next: what happens when someone believes a file shouldn't be on Hash Bin at all.
