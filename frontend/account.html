devicebasedauth.org

Use device-bound keys from devicebasedauth.org instead of API keys. Each device makes its own key, which never leaves it, and its credential says exactly what it may do here, when and where.

Checking link…

Linking lets credentials from your devicebasedauth.org account act on this HashBin account, limited to what each one grants. One devicebasedauth.org account can be linked to one HashBin account. Unlinking stops all of them here at once.

Create a device-bound key

From a terminal, with the dba command-line tool:

dba enroll --aud hashbin.org --action hashbin:content:write
dba curl -X POST -H 'Content-Type: text/plain' --data-binary @note.txt https://hashbin.org/api/content

From a web page, with the browser SDK (the key is a non-extractable WebCrypto key; call enroll from a click handler so its approval popup opens):

import { DBA } from 'https://devicebasedauth.org/sdk/dba.js';

const dba = new DBA();
if (!await dba.ready()) {
  await dba.enroll({ aud: ['hashbin.org'], grants: [{ actions: ['hashbin:content:write'] }] });
}
const response = await dba.fetch('https://hashbin.org/api/content', {
  method: 'POST', headers: { 'Content-Type': 'text/plain' }, body: 'Hello'
});

Grant HashBin scopes as actions named hashbin:<scope> (for example hashbin:balance:read); a grant's monthly spend cap becomes the key's spending limit here. hashbin:session makes the device a session: it can do everything you can on this page except create API keys or apps, approve apps, change linked sign-ins or delete the account. Grants that need approval (step-up or other gates at devicebasedauth.org) are checked with devicebasedauth.org on each use. Pages on any site can call the API with a device credential. See the API reference.

Revoking the device at devicebasedauth.org stops it everywhere, including here, usually within seconds and at most five minutes.
