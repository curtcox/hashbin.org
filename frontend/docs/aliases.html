Aliases

Hosting behavior · Personal home page · Todo app · Security · API

Give a CID a name you can repoint. Manage your aliases or look up an exact global name. There is no alias search or directory.

Global names

Each name costs $1.00 per year, regardless of length. Prepay 1–10 years from your balance; the outstanding term cannot exceed 10 years. A global name has one owner, who can change its CID for free, renew it, list a fixed price, and accept offers.

https://256t.us/@my-document redirects to the CID. The information page shows status, term, listing price and the last 100 value and ownership changes. Account identities are private.

A sale transfers the current CID and remaining prepaid term. Prices start at $1.00. The seller receives balance minus a 10% fee (minimum 10¢), rounded up to a cent. Proceeds cannot be withdrawn. An offer holds the buyer’s balance immediately, expires after 7 days by default (30 maximum), and is returned when declined, withdrawn, expired, or when another sale or suspension ends it. Accepting uses the hold without charging the buyer again.

Personal names

Personal aliases are visible only to your account. Each costs 1¢ per calendar month, prepaid for 1–120 months (12 months by default, costing 12¢). An active personal alias overrides a global alias of the same name when you resolve it with your identity.

Use the dashboard or GET /api/aliases/{name}/resolve with your session or an aliases:read key or OAuth allowance. SDK v0.5.0 adds client.resolveAlias(name), followed by client.retrieve(cid) to verify the bytes. On 256t.us use a download session, API key or OAuth credential with aliases:read or downloads:spend. An anonymous visit to the same URL resolves the global name. Signed URLs remain specific to one CID and do not accept aliases.

Up to 1,000 personal aliases per account. Changing values is free. Deleting a name or your account does not refund its prepaid months.

Names, caching and expiry

Names have 1–63 ASCII letters, digits, hyphens, underscores or dots, begin and end with a letter or digit, and cannot contain consecutive dots or be valid CIDs. Names are lowercased. Service and security names are reserved for admin assignment. Values are CIDs, including inline content and alternate suppliers; aliases cannot point to other aliases. An alias does not extend content retention.

Changes can take up to 60 seconds to reach everyone. Anonymous global redirects can be cached for up to a minute; identified responses are private and never stored by shared HTTP caches. Keep the CID if you need an immutable reference. Every account has 100 changes per UTC day, shared by personal creates, edits, settings and deletes and global value, setting and listing changes. Claims, renewals and new offers have a separate 100-per-day purchase limit.

Resolution stops at expiry. A global owner has 30 days to renew before the name returns to the pool; expired personal records are also kept for 30 days, then deleted. Global listings and offers end at expiry. Optional auto-renew attempts a renewal 7 days before expiry using balance and the previous term length. Failed renewals retry daily during grace; keep enough balance and keep the paying credential authorized. Auto-renew is disabled when a global name is sold.

Resolution follows the platform cost brake and hard stop. Abusive, impersonating or infringing names can be reported. Admins may suspend or reclaim abusive names without refund. Upheld trademark reports only suspend names; names are not reclaimed or transferred to claimants. If HashBin shuts down, alias resolution and name licenses end without refunds for unused prepaid terms. See the Terms and Privacy Policy.

What an alias can host today

https://256t.us/@alex-home sends an HTTP 302 redirect to https://256t.us/{cid}. The browser ends on the CID URL; the alias is not a custom domain, a directory, or an application runtime. /a/@alex-home redirects to /a/{cid} and requires a download identity. Alias redirects do not preserve query parameters such as ?download=true; use the resolved CID URL for those options.

The final content response keeps Content-Security-Policy: default-src 'none'; sandbox, X-Content-Type-Options: nosniff and X-Frame-Options: DENY. A basic HTML document with text and links can display when served as text/html. Scripts, inline and external styles, images and other subresources are blocked; forms cannot submit, and the sandbox does not give the document normal origin storage. Uploaded HTML cannot relax these response headers with a meta tag.

Each alias points to one file. There is no /@alex-home/about, relative asset tree, index-file routing, or automatic rewriting of links. Use explicit absolute links. For an interactive web app, serve the app shell from an HTTPS origin you control, and use HashBin for verified source releases or data snapshots. The SDK's hosted sandbox runs worker code for a registered embedding app; an alias does not turn into a hosted sandbox page.

Example: a personal home page

A home page about a person uses a global alias if everyone should be able to visit it. A personal alias is an account-only shortcut. Save this as home.html, replacing the sample name and links. It deliberately uses only HTML that works under the content host's restrictions.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Alex Rivera — home</title>
<main>
  <h1>Alex Rivera</h1>
  <p>I build small tools and write about the web.</p>
  <h2>Projects</h2>
  <ul>
    <li><a href="https://example.com/projects">My projects</a></li>
    <li><a href="https://todo.example.com/">My todo app</a></li>
  </ul>
  <p><a href="https://example.com/contact">Contact me</a></p>
</main>
</html>
  1. Upload home.html through the upload page, or use the raw upload below. Preserve the text/html content type and copy the returned cid.
  2. Look up alex-home on the alias information page and claim it if available, choosing the uploaded CID. One year costs $1.00, in addition to content retention.
  3. Share https://256t.us/@alex-home. Open it anonymously to confirm the global target, without a personal override.
  4. For an update, upload the edited file and change the alias value to the new CID in the dashboard. The old CID still identifies the old bytes; changing an alias does not delete them. Allow up to 60 seconds for the new target to propagate.

These command-line examples use an API key kept in the HASHBIN_API_KEY environment variable, never in the page. Upload requires content:write, claiming requires aliases:purchase, and changing a value requires aliases:write. Fund its account and grant enough spending capacity. Replace each CID placeholder with the complete returned CID. Upload and alias purchase are separate operations.

curl --fail-with-body --silent --show-error \
  'https://hashbin.org/api/content?retention_months=12' \
  -H "Authorization: ApiKey $HASHBIN_API_KEY" \
  -H 'Content-Type: text/html; charset=utf-8' \
  --data-binary @home.html

# Claim an available name; keep this ID for retries of this exact purchase.
CLAIM_REQUEST_ID="$(uuidgen)"
curl --fail-with-body --silent --show-error \
  https://hashbin.org/api/aliases/alex-home/claim \
  -H "Authorization: ApiKey $HASHBIN_API_KEY" \
  -H 'Content-Type: application/json' \
  --data "{\"cid\":\"YOUR_HOME_CID\",\"years\":1,\"request_id\":\"$CLAIM_REQUEST_ID\"}"

# After uploading an edited home.html, repoint the name for free.
curl --fail-with-body --silent --show-error --request PUT \
  https://hashbin.org/api/aliases/alex-home/value \
  -H "Authorization: ApiKey $HASHBIN_API_KEY" \
  -H 'Content-Type: application/json' \
  --data '{ "cid": "YOUR_NEW_HOME_CID" }'

Renew both the alias and the content as needed: paying for the name does not keep the home page bytes available. Use a dedicated conventional web host if your home page needs styling, images, forms or scripts.

Example: a todo app and its backups

This small app adds, completes and deletes tasks, stores them in this browser, and exports a JSON backup. Save it as todo.html and serve it from an HTTPS app origin you control, such as https://todo.example.com/. Its script and storage will not work when opened directly through a 256t.us alias. No HashBin credentials or registration are needed for this local-storage example.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>My todos</title>
<h1>My todos</h1>
<p>Stored in this browser only. Export a backup before clearing site data.</p>
<form id="add">
  <label>Task <input id="task" maxlength="200" required></label>
  <button>Add</button>
</form>
<ul id="tasks"></ul>
<button id="export" type="button">Export JSON backup</button>
<p id="status" role="status"></p>
<script type="module">
const key = 'alex-todos-v1';
const list = document.querySelector('#tasks');
const input = document.querySelector('#task');
const status = document.querySelector('#status');
let tasks = [];
try {
  const saved = JSON.parse(localStorage.getItem(key) || '[]');
  if (!Array.isArray(saved) || saved.length > 1000 || saved.some(task =>
    !task || typeof task.text !== 'string' || task.text.length > 200 ||
    typeof task.done !== 'boolean')) throw new Error('Invalid backup');
  tasks = saved;
} catch {
  status.textContent = 'Saved tasks could not be loaded; new edits start a fresh list.';
}
function save() {
  try {
    localStorage.setItem(key, JSON.stringify(tasks));
    status.textContent = 'Saved in this browser.';
  } catch {
    status.textContent = 'Browser storage unavailable or full. Export a backup.';
  }
  render();
}
function render() {
  list.replaceChildren();
  tasks.forEach((task, index) => {
    const row = document.createElement('li');
    const label = document.createElement('label');
    const check = document.createElement('input');
    check.type = 'checkbox';
    check.checked = task.done;
    check.addEventListener('change', () => { task.done = check.checked; save(); });
    const text = document.createElement('span');
    text.textContent = task.text;
    label.append(check, text);
    const remove = document.createElement('button');
    remove.type = 'button';
    remove.textContent = 'Delete';
    remove.addEventListener('click', () => { tasks.splice(index, 1); save(); });
    row.append(label, remove);
    list.append(row);
  });
}
document.querySelector('#add').addEventListener('submit', event => {
  event.preventDefault();
  const text = input.value.trim();
  if (!text) return;
  if (tasks.length >= 1000) {
    status.textContent = 'Limit of 1,000 tasks reached. Export and remove old tasks.';
    return;
  }
  tasks.push({ text, done: false });
  input.value = '';
  save();
});
document.querySelector('#export').addEventListener('click', () => {
  const file = new Blob([JSON.stringify(tasks, null, 2)], { type: 'application/json' });
  const url = URL.createObjectURL(file);
  const link = document.createElement('a');
  link.href = url;
  link.download = 'todos.json';
  link.click();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
});
render();
</script>
</html>

For production, move the inline script into a file on your app origin and restrict script-src to that origin, or allow only the script's exact hash in your CSP. Keep this app on a dedicated origin if other hosted apps are not equally trusted.

To publish a named source release, upload todo.html as text/html and claim a global name such as alex-todo-source using the home-page flow. Repoint it after publishing a new release. The alias shares the app's source artifact; visitors run the app at your separate app URL. Publish a simple HTML landing page linking to that URL if you want a directly usable alias entry page. An alias value cannot itself be an external app URL.

Keep a named data snapshot

Export todos.json and upload it as application/json instead of HTML. The example data below is public once uploaded. Create a personal alias todo-backup to remember its latest CID; it costs 12¢ for 12 months. These are authenticated JSON API requests, with aliases:purchase for creation and aliases:write for updates. Use a fresh unique purchase request ID, and reuse it only for the same retry.

[{ "text": "Water the plants", "done": false }]

POST /api/user/aliases/personal
{ "name": "todo-backup", "cid": "YOUR_JSON_CID", "months": 12, "request_id": "UNIQUE_PURCHASE_ID" }

# Export and upload a new JSON file before changing the pointer.
PUT /api/user/aliases/personal/todo-backup
{ "cid": "YOUR_NEW_JSON_CID" }

The export button only downloads a local file; it does not upload, create or update aliases. This sample has no automatic cloud sync or restore. For an app that retrieves a snapshot, use the following with an already configured SDK v0.5.0 client authorized for aliases:read (see the allowance and callback guide). Validate the parsed JSON against your app's schema and limits before offering an explicit import; display task strings with textContent.

const cid = await client.resolveAlias('todo-backup');
const response = await client.retrieve(cid); // Verifies bytes against this CID.
const snapshot = await response.json();     // Still untrusted application data.

An expired or missing personal alias falls back to the global name, even for an identified caller. Apps that require a personal result should check source === 'personal' in the authenticated GET /api/aliases/todo-backup/resolve response before retrieving it. An anonymous visitor cannot resolve your personal record. That does not make the JSON private: anyone with its CID can retrieve it. Encrypt sensitive task data before uploading, and keep the decryption key outside the published content and alias.

Aliases provide a mutable pointer to an immutable snapshot, without transactions across upload and repoint, edit merging or conflict detection. Concurrent saves can overwrite the pointer; a failed repoint can leave an uploaded snapshot unreferenced. Keep backup CIDs and handle failures before reporting a successful save.

Security implications for pages and web apps

  • A name is mutable, not proof of identity. Owners can change targets, sell names, or lose them after expiry and the 30-day grace. A buyer or later claimant can publish different content at a familiar link. Inspect the current CID and public history; a paid name is not an endorsement or proof of a person's identity. Avoid treating an alias as a permanent trusted login or payment destination.
  • Pin code you trust. A CID verifies bytes, not their author or safety. Resolving an alias and then verifying the returned CID still accepts whichever version the name currently selects. Review and pin an expected CID for executable releases; use a versioned SDK URL with SRI. Never load executable code from a mutable alias into a page that holds credentials without an explicit review and upgrade decision.
  • Keep origin boundaries. Alias names and CID paths do not create separate browser origins. The content host's sandbox prevents scripts and gives documents opaque origins; do not strip its headers in a proxy to make apps run. A proxy or host that executes multiple users' apps under different paths of one origin exposes shared storage and authority. Give mutually untrusted apps separate origins, or use a sandbox with deliberately limited capabilities. HashBin's dashboard and sessions stay on a separate origin.
  • Protect credentials and stored data. Never publish API keys, bearer tokens, decryption keys or personal task data in HTML or source. On your own app origin, injected or compromised scripts can read localStorage and use active browser allowances. Render user input as text, keep dependencies pinned, and use a restrictive CSP. Prefer per-save approval; when delegation is needed, request only necessary scopes, short expiry and small spending limits. A DPoP key does not prevent a script already running in its app origin from using the allowance.
  • Personal names protect the mapping, not the content. Global CIDs and their last 100 value/ownership changes are public. Personal mappings require your identity, but content remains free to retrieve by CID, and aliases are not access control or encryption. Avoid secrets in names and public history; consider encrypting content before upload. Deleting or repointing a name does not revoke copies or remove an old CID.
  • Resolve with the intended identity. The same link can select your personal override or the global record. Signing in to hashbin.org alone is not a download identity on 256t.us; use its download session or a permitted API/OAuth credential. The strict /a/ route requires identity but still permits global fallback. Do not assume an anonymous share link opens your private mapping, or that fallback data is trusted. Never put credentials in URLs.
  • Plan for availability and stale pointers. Names expire or can be suspended; content retention expires separately. Changes may take 60 seconds, and rate limits, cost brakes or unavailable suppliers can interrupt resolution/download. Handle those failures, retain known-good CIDs, and never bypass integrity verification or silently execute an unexpected replacement.

See content security, browser client safety and security notes. Browser behavior is defined by the CSP sandbox specification and HTML origin model.

API example

POST /api/user/aliases/personal
{ "name": "my-document", "cid": "YOUR_CID", "months": 12, "request_id": "unique-id" }

GET /api/aliases/my-document/resolve
{ "cid": "YOUR_CID", "source": "personal" }

Use aliases:read, aliases:write, aliases:purchase and aliases:sell for their respective actions. Purchases share key/grant spending limits with uploads and downloads. Supply a unique request_id on purchases and reuse it only to retry the same operation; receipts are retained for 31 days. API guide.
