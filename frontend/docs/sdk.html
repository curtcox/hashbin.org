Browser SDK

Choose a safe save flow. publish() now uses HashBin-hosted approval without giving the app tokens. Token-based uploads use save().

Save with per-save approval (recommended)

const client = hashbin.createClient({
  clientId: "app_123",
  redirectUri: "https://your-app.example/hashbin/callback"
});

// Call directly from a click handler, before awaiting other work.
saveButton.onclick = async () => {
  const result = await client.publish(documentBytes, { contentType: "text/plain" });
  console.log(result.cid);
};

The user signs in, reviews the safe preview and exact price, then approves on HashBin. Popup mode supports up to 5 MiB; redirects support up to 512 KiB. If a popup is blocked, small documents fall back to redirect. Call handlePublishCallback() on the registered callback page to verify a redirect result. Pass clientState to preserve editor state through a redirect; it is returned with the verified CID. For Cross-Origin-Opener-Policy: same-origin, choose redirect mode or allow popups with same-origin-allow-popups.

Opt into an allowance for silent saves

await hashbin.authorize({
  scopes: ["content:write", "balance:read"],
  mode: "popup",
  spendingLimit: 1,       // US dollars per month
  maxUploadBytes: 1048576 // 1 MiB per upload
});

HashBin Publish offers an allowance setup link, then the user chooses caps and expiry on HashBin. Tokens are bound to a non-extractable browser key (DPoP). Access tokens last 15 minutes; refresh tokens have a seven-day idle timeout and a 90-day absolute lifetime. The default consent expiry is 30 days. If IndexedDB is unavailable, tokens and keys stay in memory and authorization requires popup mode. For popup flows, call mode: "popup" and let your callback page call hashbin.handleCallback({ postMessageToOpener: true, closeWindow: true }).

Publish, retrieve, and read balance

const balance = await hashbin.getBalance();
console.log(balance.balance_cents);

const result = await hashbin.save("hello world", {
  maxCostCents: 0, // hello world is inline and free
  contentType: "text/plain"
});

console.log(result.cid, result.url);

const contentUrl = hashbin.getContentUrl(result.cid, { download: true });
const response = await hashbin.retrieve(result.cid); // verifies bytes before returning
const bytes = await response.arrayBuffer();
console.log(await hashbin.verifyCID(result.cid, bytes));
await hashbin.disconnect(); // revokes app access, then clears local tokens

API and migration notes

publish(content, { mode, contentType, clientState }) opens approval. save(content, { contentType, maxCostCents }) uploads using an allowance. Both verify the returned CID. retrieve(cid) returns a Response only after fully verifying its bytes; streaming is unavailable. verifyCID(cid, content) returns a boolean and accepts strings, Blobs, ArrayBuffers and typed-array views.

Previously publish() uploaded with OAuth. Replace those calls with save() to keep silent-save behavior. To remove credentials from your client, use the new publish() flow and remove the authorization code. Old unbound grants continue within their expiry; new SDK authorization requests are DPoP-bound. All refresh requests must now include client_id. Existing rotated-token reuse revokes the grant, so clients outside the SDK must serialize refreshes.

For raw uploads, append ?max_cost_cents=INTEGER to POST /api/content. A charge above that ceiling returns 409 max_cost_exceeded before debit or storage. Negative, fractional, empty and unsafe values return 400. The SDK sends this ceiling from maxCostCents.

Custom DPoP implementations obtain a five-minute server nonce from GET /oauth/dpop-nonce, then send an ES256 proof in the DPoP header on token requests and resource requests. Use Authorization: DPoP ACCESS_TOKEN for resources, including ath; include dpop_jkt on authorization. Proofs require a unique jti, exact htm, a query-free htu, and iat within 60 seconds. Refresh and access tokens retain the same binding. The SDK handles this automatically.
