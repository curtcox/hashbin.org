Security notes

Browser client safety · SDK guide · Documentation

This is HashBin's running record of security problems found in HashBin and in apps that use it. Each note explains what was wrong, how it was detected, how it can be demonstrated and how it was fixed, so other developers can avoid the same problem. Notes are added as HashBin is used, and updated when fixes ship.

HashBin first. Every note answers one question: can HashBin remove this problem for every app, once? When it can, that fix comes first, and the app-side change is a stopgap or fallback.

How a note is written

  1. Summary: who is affected, the impact and the current status.
  2. Facts: dates found, mitigated, fixed and published; affected versions; severity; commits.
  3. What was wrong: the mechanism.
  4. How it was detected, and what would have caught it sooner.
  5. How it can be demonstrated: a local test with test data only. It becomes the regression test.
  6. How it was fixed: HashBin-side, app-side, and options rejected.
  7. How to avoid it: the general rule for other developers.
  8. Lessons for HashBin's process, checks and documentation.

HashBin also runs a safety check on registered apps, on request and nightly, that looks for the problems recorded here.

Analysis and the fix plan are published when a note opens. Demonstration material for a problem on a live, shared origin is published after the fix ships, or 30 days after the affected owner is told. Owners of third-party apps are told before their note opens.
