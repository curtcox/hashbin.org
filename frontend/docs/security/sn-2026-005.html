SN-2026-005: Cross-origin isolation severs the Publish popup

An app that serves Cross-Origin-Opener-Policy: same-origin, usually for crossOriginIsolated and SharedArrayBuffer, cannot receive the result from HashBin Publish's popup. The SDK sees the popup as closed and reports a failed save.

Found2026-10-28, migrating apptron to publish()
AffectedSDK v0.2.0 popup mode in apps sending that header
SeverityLow: saves fail; nothing is exposed
StatusMitigated in apptron; SDK fix planned

What was wrong

That header places a cross-origin popup in a separate browsing context group. The opener loses its reference, so no result can come back over postMessage.

How it was detected

Reading the app's service worker during migration: it adds the header to every response.

How it can be demonstrated

Serve a page with the header, call publish() in popup mode, and observe the "Publish window closed" error.

How it was fixed

  • App-side: apptron uses mode: 'redirect' when crossOriginIsolated is true.
  • HashBin-side (planned): the SDK detects a severed popup and falls back to redirect itself.

How to avoid it

Use redirect mode in isolated apps, or same-origin-allow-popups if isolation is not required.
