SN-2026-006: A cancelled redirect save loses the app's saved state

In redirect mode the SDK stores the document and optional clientState while the user visits HashBin. If the user cancels, handlePublishCallback() discards the stored state and only throws the error, so an app without its own draft storage loses the user's work.

Found2026-10-28, migrating ManimOnline, which keeps no local draft
AffectedSDK v0.2.0
SeverityLow: data loss, not exposure
StatusFixed in SDK v0.3.0 (2026-10-28)

What was wrong

The callback removes its transaction before checking for an error, and the error path returns nothing.

How it was detected

Tracing the cancel path while adding redirect support to an app without draft persistence.

How it can be demonstrated

Publish in redirect mode with clientState, choose Cancel on HashBin, and call handlePublishCallback(): it throws access_denied with no state.

How it was fixed

  • App-side: each app keeps its own session copy of the document before publishing and restores it on error.
  • HashBin-side (SDK v0.3.0): cancelled, expired and mismatched callbacks throw an error carrying clientState, so the app copies were removed.

How to avoid it

Upgrade to SDK v0.3.0 and restore from error.clientState in your callback's error path. On v0.2.0, keep a session copy of anything you pass as clientState.
