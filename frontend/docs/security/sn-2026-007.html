SN-2026-007: Redirect saves are limited to 512 KiB

Redirect mode carries the document in the URL fragment, so the SDK limits it to 512 KiB. Apps that must use redirect mode, such as cross-origin isolated apps, cannot publish larger documents directly.

Found2026-10-28, migrating apptron, whose disk overlays can reach 5 MiB
AffectedRedirect-only apps
SeverityLow: a usability limit
StatusFixed in SDK v0.3.0 (2026-10-28)

What was wrong

Fragment length is the only channel a redirect offers without a server-side handoff.

How it was detected

Comparing apptron's overlay size limit with the SDK's redirect limit.

How it can be demonstrated

With SDK v0.2.0, call publish() in redirect mode with more than 512 KiB: the SDK refuses. The SDK and Publish page tests now cover the file handoff instead.

How it was fixed

  • App-side: apptron asks the user to download the file and upload it on hashbin.org.
  • HashBin-side (SDK v0.3.0): an explicit redirect save above 512 KiB downloads the document as a file and records its CID. The Publish page asks the user to choose that file and accepts only bytes matching the CID; the callback checks the returned CID against the recorded one.

How to avoid it

Upgrade to SDK v0.3.0 and pass fileName so the downloaded file is easy to find. A blocked popup still falls back to the fragment only up to 512 KiB; larger documents need the popup or explicit mode: 'redirect'.
