SN-2026-008: Local security tests failed without a signing key

The local Worker configuration had no OAUTH_SIGNING_KEY. Hosted approval and DPoP returned errors, so the cross-origin browser safety tests failed locally for a reason unrelated to the code under test.

Found2026-10-28, re-verifying the browser client safety measures
Fixed2026-10-28: .dev.vars.example and local setup documentation
AffectedHashBin development only
SeverityNone in production; risk of ignoring security test failures
StatusFixed

What was wrong

wrangler.local.toml defines no signing key, and no example .dev.vars existed. A previous developer environment must have had one.

How it was detected

The tests failed with HTTP 500 from /api/publish; the worker code reads env.OAUTH_SIGNING_KEY.

How it was fixed

Copy .dev.vars.example to .dev.vars and set a random local-only key, or pass --var OAUTH_SIGNING_KEY:… to wrangler dev. Never reuse the production key.

Lessons

Security tests that fail for environment reasons get ignored. Local setup must make them pass by default.
