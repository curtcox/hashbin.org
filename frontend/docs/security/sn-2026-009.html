SN-2026-009: Sanitizers trigger Content-Security-Policy reports

When DOMPurify sanitizes markup containing inline event handlers, the browser can report script-src-attr violations from DOMPurify's internal document. Nothing runs, but tests that fail on any violation report fail.

Found2026-10-28, adding a policy check to the Sheets gallery tests
AffectedApps that test their policy and sanitize untrusted markup
SeverityNone: the handlers are refused and then removed
StatusAccepted

What was wrong

The sanitizer parses untrusted markup in a document that shares the page's policy before it removes the handlers. The browser reports the handler it refused.

How it was detected

A gallery example that deliberately contains a handler produced one report. The report's source file pointed into the sanitizer, and a check confirmed the handler never ran.

How to avoid it

In policy tests, ignore script-src-attr reports whose source file is the sanitizer, and keep an assertion that the handler did not run.
