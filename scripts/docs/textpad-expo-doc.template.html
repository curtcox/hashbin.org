Textpad for Expo

What it is

This is Textpad, HashBin's example text editor, rebuilt as an iOS and Android app with Expo and React Native. It does the same things as the web version, and this page explains the parts that work differently on a phone. There is also a Flutter version.

  • Open: a link such as org.hashbin.textpad.expo://open?256t=<256t string> opens Textpad with that text. Users can also paste a 256t string, a 256t.us link or a web Textpad link into the Open field.
  • Edit and save: Save publishes the text to the user's HashBin account. Copy link then copies a link that opens the text in any browser.
  • Pay with the user's account: the user approves Textpad once on hashbin.org, inside the app, and stays connected.
  • Explain problems: a malformed 256t string, one with nothing stored under it, or content that isn't text each gets its own message.

The project is in the HashBin repository at examples/textpad-expo. The code is in three files:

textpad.js256t strings, links and text decoding. Plain JavaScript with no React Native, so it is tested under Node.
hashbin.jsA small HashBin OAuth client: sign-in, token storage and renewal, and API calls. Copy it into your own app.
App.jsThe screen, and what happens when the user taps something.

Try it

Install the app on a phone or simulator first. These links then open in it; short texts need no account, because they are stored inside the 256t string itself.

LinkWhat you'll see
A short text "Hello from Textpad! Edit me, then click Save." Edit it and tap Save to try saving.
A malformed 256t string An error saying the string isn't a valid 256t string.
Content that isn't text An error saying the content isn't text.

In the simulator you can open a link from a terminal: xcrun simctl openurl booted "org.hashbin.textpad.expo://open?256t=…" on iOS, or adb shell am start -a android.intent.action.VIEW -d "org.hashbin.textpad.expo://open?256t=…" on Android.

Signing in from an app

A phone app signs in to HashBin with the same OAuth 2.0 and PKCE flow as a web page. Four things are different:

  • The approval page opens in an in-app browser. On iOS this is an ASWebAuthenticationSession, on Android a Chrome Custom Tab. The user sees the real hashbin.org address, and it shares the browser's sign-in, so they often don't need to sign in again. iOS first asks "Textpad Wants to Use hashbin.org to Sign In"; that prompt comes from the system, not from HashBin.
  • The redirect URI uses the app's own URL scheme: org.hashbin.textpad.expo://oauth. The scheme is set in app.json, and the system hands links that use it to this app. HashBin accepts redirect URIs like this when the scheme is named after a domain, written backwards (RFC 8252). A plain name such as textpad:// is refused, because any app could claim it.
  • Tokens are kept in secure storage, the iOS Keychain or the Android Keystore, through expo-secure-store. A web page has to use localStorage.
  • Nothing has to survive a page change. The app keeps running while the browser is open, so unlike the web version it doesn't save the user's text before signing in.

Everything else matches the web version. Textpad asks for content:write and balance:read. Each save is charged to the user's balance and kept for the default retention period set on their account page, and texts of 64 bytes or less are free. Disconnect revokes the app's access on the server, and users can also revoke Textpad from their account page.

The code, step by step

The excerpts below are copied exactly from the app; the full source is at the end of this page.

1. Configuration

App.js starts by naming the app (its client ID), where HashBin is, and the redirect URI. EXPO_PUBLIC_ environment variables let a developer point the app at a local HashBin server without editing the code. Expo copies them into the app when it is bundled, so a published app always uses hashbin.org.

@@EXCERPT start="// The HashBin service, and the domain" term="});"@@

The redirect URI's scheme is the one in app.json:

@@EXCERPT file="app.json" start=" "scheme"" term=" "scheme""@@

2. Finding the 256t string in a link

Textpad accepts its own deep links, and also the links people are likely to have: a web Textpad link, a raw 256t.us link, or just the string. It ignores links that hold no 256t string, such as the one that ends a sign-in.

@@EXCERPT file="textpad.js" start="// Textpad opens a 256t string from any of these:" anchor="export function cidFromText" term="}"@@

3. Checking a 256t string

A 256t string has two parts, both in base64url. The first 8 characters hold the content's length in bytes. The rest is the content itself when it is 64 bytes or less, or else its SHA-512 hash, which is always 86 characters. Checking that the two parts agree catches typos and truncated links before any network request is made:

@@EXCERPT file="textpad.js" start="// A 256t string is base64url text" anchor="export function isValid256t" term="}"@@

4. Turning bytes into text

HashBin stores bytes, not text, and React Native has no strict UTF-8 decoder. JavaScript's decodeURIComponent is one, though: given the bytes as %XX escapes, it throws on anything that isn't valid UTF-8.

@@EXCERPT file="textpad.js" start="// Content on HashBin is just bytes." anchor="export function decodeText" term="}"@@

5. Opening a text

Opening checks the string, then either decodes a short text straight from it or downloads a longer one from https://256t.us/<string>. Downloading needs no account. Each failure gets its own message, and the editor is emptied first, so nothing on screen can be mistaken for the content of a broken link.

@@EXCERPT start=" async function openCid(cid) {" term=" }"@@

6. Signing in

connect() in hashbin.js builds the authorization link with a PKCE challenge, opens it with WebBrowser.openAuthSessionAsync, and waits. When HashBin redirects to org.hashbin.textpad.expo://oauth?code=…, the browser closes and hands that link back. The app checks the state, then trades the code for tokens.

@@EXCERPT file="hashbin.js" start=" // Opens HashBin's approval page" anchor=" async connect() {" term=" }"@@

7. Renewing access

Access tokens last an hour. Every API call goes through account.fetch(), which renews an expired token first. Refresh tokens work only once, so calls that need a new token at the same moment share a single renewal. A refused refresh token, or a 401 from the API, means the user has to approve Textpad again.

@@EXCERPT file="hashbin.js" start=" // Access tokens last an hour." anchor=" async renewTokens() {" term=" }"@@ @@EXCERPT file="hashbin.js" start=" // fetch() for HashBin API paths" term=" }"@@

8. Saving text

Save connects first if needed, then sends one POST /api/content whose body is the text. The response holds the new 256t string (cid).

@@EXCERPT start=" async function save() {" term=" }"@@

9. Receiving links

React Native's Linking module gives the link that launched the app, and then any link opened while it runs. The listener is set up once, so it calls the newest openLink through a ref; otherwise it would see the text as it was when the app started.

Run it

You need Node.js, plus Xcode for iOS or Android Studio for Android. Textpad uses its own URL scheme, so it needs a development build; it can't run in Expo Go, which has a scheme of its own. 

git clone https://github.com/curtcox/hashbin.org.git
cd hashbin.org/examples/textpad-expo
npm install
npx expo run:ios        # or: npx expo run:android

The first run builds the native app, which takes a few minutes. After that, edits to the JavaScript reload instantly.

Make your own app from it

  1. Pick a URL scheme from a domain you control, written backwards, for example com.example.notes. Set it as scheme, ios.bundleIdentifier and android.package in app.json.
  2. Register an app on the Developers page with the redirect URI com.example.notes://oauth.
  3. In App.js, set REDIRECT_URI to that address and CLIENT_ID to your app's client ID.
  4. Rebuild the native app (npx expo prebuild --clean, then npx expo run:ios), since the scheme is part of it.

Against a local HashBin server

Start the server with npm run dev:local in the repository root. On its Developers page, register an app with the redirect URI org.hashbin.textpad.expo://oauth. Then run: 

EXPO_PUBLIC_HASHBIN_URL=http://127.0.0.1:8787 \
EXPO_PUBLIC_TEXTPAD_CLIENT_ID=<client ID> \
npx expo run:ios

In the Android emulator, the computer is 10.0.2.2 instead of 127.0.0.1. Expo copies these variables into the app when it bundles the JavaScript, so restart with npx expo start --clear after changing them.

Things to know

  • Copied links point to the web. Copy link copies a link to the web version of Textpad, which opens in any browser on any device; pasting it into this app's Open field works too.
  • Saving the same text again. Save stays disabled until the text changes. If edited text happens to match something already on HashBin, HashBin keeps the existing copy and extends how long it is kept, which is charged like a new save.
  • Saves use the account's default retention. Apps cannot choose how long content is kept; users set their default on the account page.
  • Android can close a backgrounded app. If the phone is very short of memory while the approval page is open, Android may close Textpad, and unsaved text would be lost. A production app could keep a draft in storage to guard against this.
